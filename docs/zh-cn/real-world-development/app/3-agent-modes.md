前面我们为项目添加了一项小功能。较大的更改需要更完善的流程。GitHub Copilot app 可融入组织现有的开发流程，帮助团队以正确的方式构建正确的功能。从本课开始，你将遵循常见的智能体开发流程：根据议题生成新功能，确认代码有效、功能符合预期，最终成功合并到项目中。

> [!NOTE]
> 后续课程会继续使用同一会话处理该功能。实际工作中，通常会为不同文件类型使用不同会话或 PR；本工作坊会简化流程，以便专注于核心概念。

本课将：

- 从 GitHub 议题启动新的智能体会话。
- 使用 **Plan** 模式确定需求。
- 使用 **Autopilot** 模式实现新功能。
- 审查代码。
- 在浏览器画布中手动验证功能。

在继续开发此功能时，你还将更新存储库指令、自定义现有质量检查技能、添加模型上下文协议（MCP）验证、创建质量保证（QA）智能体，并创建功能 PR。

## 场景

Tailspin Toys 的目录不断扩大，访客需要按类别和发行商筛选游戏。待办议题描述了该功能，但例如如何组合多个类别等细节需要在编码前商定。你将使用 Plan 模式明确这些决定，然后授权 Autopilot 在限定范围内实现功能。

## 背景

在开发流程中引入人工智能（AI）编码智能体并不会改变基本原则，反而使这些原则更加重要。大多数开发者的流程大致如下：

1. 打开描述待办事项的议题。
2. 制定要构建内容的计划。
3. 构建并审查代码。
4. 运行测试以验证代码。
5. 手动验证新功能。
6. 创建拉取请求（PR）。
7. 代码经过审查且持续集成流程成功后，合并代码。

> [!NOTE]
> 具体流程因团队和组织而异，但大多数流程都与上述步骤类似。

遵循标准流程可以确保 AI 生成的代码满足需求，并像手写代码一样经过验证。

## 会话模式

**会话模式**控制智能体的自主程度。你可以从提示框下方的下拉菜单中设置模式，也可以随时更改：

- **Interactive**：你与智能体协作。智能体提出更改建议，并等待你输入后再继续。
- **Plan**：智能体先创建计划。你审查并批准计划后，智能体才会执行。
- **Autopilot**：智能体完全自主地编写代码、运行测试并迭代，无需等待输入。

先使用 Plan 模式，审查计划，然后使用 Autopilot 实现计划。

## 从议题启动会话

开始前，确认星级评分 PR 已合并，并且本地 `main` 分支已更新。随后从现有议题启动会话。

1. 在侧边栏的 **Sessions** 下选择 Tailspin Toys 存储库文件夹，然后在存储库顶部导航中选择 **Issues**。打开 **Allow users to filter games by category and publisher**。这是模板预置议题，无需再创建。
2. 选择 **New session**，并选择基于已更新 `main` 分支的**新工作树**。

   ![GitHub Copilot app 中的议题视图，箭头指向 New session 按钮](../../../_images/app-new-session-from-issue.png)

3. 确认议题已附加到会话，然后在模式选择器中选择 **Plan**。

> [!NOTE]
> 如果找不到 Node.js 或 npm，请让智能体运行 `node --version` 和 `npm --version`。如果它们在终端中可用，但在会话中不可用，请检查 app 的 PATH 或版本管理器设置，然后彻底退出并重新打开 app。重试失败的操作和检查；不要仅因智能体找不到 npm 就重新安装 npm。

## 规划筛选功能

先制定计划，你可以在 Copilot 编写代码前审查实现方案。由于会话从议题启动，Copilot 已将功能请求作为上下文。请发送以下提示并确认需求：

1. 输入并发送：

   ```plaintext
   Build this feature.
   ```

2. 回答 Copilot 的问题，并将计划与议题的验收标准进行比较。
3. 确认计划涵盖类别和发行商筛选、可访问的控件、数据访问更改和测试。讨论任何不明确的行为，例如多个类别的组合方式或没有游戏匹配时的处理方式。
4. 确认计划使用项目现有工具运行 lint、单元测试、端到端（E2E）测试和类型检查。计划应聚焦于实现和测试筛选功能；完成质量工作流前不要创建 PR。
5. 要求 Copilot 修改计划中的问题，再批准计划。保留议题 URL 和商定的澄清信息，以便后续验证。

## 明确批准 Autopilot

满意后批准计划，并确认会话确实切换到了 Autopilot。批准操作可能会立即开始实现，因此在执行前务必审查计划。

1. 选择 **Approve and implement this plan**，或当前版本中含义相同的选项。
2. 查看模式指示器，确认当前模式为 **Autopilot**，不要假设批准计划会自动切换模式。
3. 让 Copilot 按计划完成实现，并检查其进度和测试结果。

> [!NOTE]
> 如果 Copilot 报告缺少依赖项或端口冲突，请先解决环境问题，再判断检查是否完成。只停止由你启动的服务器。

## 审查和验证实现

与其他代码一样，生成的代码在合并前也需要审查。先检查实现和自动检查，再启动网站进行手动验证。

1. 打开 **Changes**，检查筛选功能实现和测试。
2. 对照议题和已批准的澄清信息检查结果，包括多个类别及发行商组合，并确认更改符合现有存储库指令。
3. 检查 lint、单元测试、E2E 测试和类型检查的结果。跳过的检查不算通过。
4. 解决失败项并重新运行受影响的检查。Playwright 的 E2E 配置会构建并提供预览服务，也可能复用本地服务器；确认被测服务器属于此工作树，而不是前一课遗留的服务器。

## 体验新功能

代码审查通过后，在浏览器画布中启动应用并检查筛选行为。

1. 使用以下提示请求 Copilot 启动应用并在浏览器画布中打开页面：

   ```plaintext
   Start the app and open it in the browser canvas.
   ```

2. 等待应用启动，并在 Copilot app 中打开浏览器窗口。
3. 选择一个类别，确认显示结果与该类别匹配。清除筛选，再选择一个发行商，确认结果与该发行商匹配。
4. 组合类别和发行商筛选，并根据议题和已批准计划检查结果。如果支持多个类别，还要验证已商定的组合行为。
5. 测试一个没有匹配游戏的筛选组合并检查空状态。清除或重置筛选，确认完整游戏列表重新显示。
6. 检查完毕后，使用以下提示请求 Copilot 停止本会话启动的开发服务器：

   ```plaintext
   Stop the dev server and close the browser canvas.
   ```

## 保留此会话以供后续使用

现在不要创建或合并筛选功能 PR。请保留此会话、工作树和分支，供后续课程继续使用。接下来会为筛选代码应用自定义指令，再添加技能和 QA 改进，最后创建并合并功能 PR。停止开发服务器后，可以让会话保持空闲，并在后续课程中返回同一会话。

- 使用 **Autopilot** 模式实现了新功能。
