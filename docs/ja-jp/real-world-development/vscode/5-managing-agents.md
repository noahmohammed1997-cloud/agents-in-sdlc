GitHub Copilot を agent mode で使うと、コードベースを調べ、変更を提案してファイルを編集し、コマンドを実行するなど、自律的に作業します。VS Code の Copilot Chat では、ローカル環境でリアルタイムに実行されるツール呼び出しやファイル編集を確認できます。差分をインラインでレビューし、個々の変更を受け入れたり取り消したりできます。また、エディターを離れずに追加のプロンプトを送り、作業を調整したり拡張したりできます。

この演習では、次のことを行います。

- アクセシビリティ エージェントの作業をリアルタイムで監視します。
- 提案されたファイル編集をレビューして受け入れます。
- 実行中のセッションに指示を追加し、ハイ コントラスト モードにライト モードの切り替え機能を加えます。

## シナリオ

[演習 4][previous-lesson]で使ったアクセシビリティ用カスタム エージェントは、ハイ コントラスト モードを実装しています。作業中、デザイン チームから、既定のテーマが暗すぎると感じる利用者向けにライト モードも追加してほしいという依頼がありました。新しい会話を始める代わりに、既存のセッションに指示を追加して作業を拡張します。

## Copilot の進捗を監視する

Copilot Chat ビューには、エージェントが調べたファイル、実行したコマンド、提案した編集などの各ステップが表示されます。ファイル編集は差分と **Keep** / **Undo** の操作とともにチャット内に表示されます。

1. 演習 4 で使った Copilot Chat ビューに戻ります。
2. エージェントが作業している間、チャットをスクロールしてツールの操作を確認します。ファイルの読み取りや編集、実行を求めるターミナル コマンドが表示されます。
3. エージェントがファイルを編集すると、差分がチャット内に表示されます。
   1. 変更を受け入れるには **Keep** を選択します。
   2. 変更を取り消し、エージェントにもう一度作業させるには **Undo** を選択します。
4. チャット上部の **Files changed** の表示を開くと、このセッション中にエージェントが変更したファイル全体を確認できます。

> [!NOTE]
> ターミナル コマンドの実行などでツールの許可を求められた場合、エージェントは一時停止して **Allow** を表示します。実行してよいコマンドだけを許可してください。

5. エージェントがハイ コントラスト モードを実装し終えるまで待ちます。完了すると、変更の概要が表示されます。

## ライト モードを追加するようエージェントに指示する

ハイ コントラスト モードの実装が終わったら、同じ会話でライト モードの切り替え機能を追加します。同じチャット セッションを続けると、エージェントは前の作業で扱ったコンポーネント、スタイルの方針、local storage のパターンなどのコンテキストを保持します。

1. Copilot Chat の入力欄に、次の追加プロンプトを送信します。

   ```plaintext
   Nice work! Now add a light-mode toggle alongside the high-contrast toggle. Light mode should follow the same pattern — persist via local storage and be accessible from the same area of the UI. The user should be able to enable high-contrast and light mode independently.
   ```

2. エージェントは既存の変更を調べ、ライト モードの追加を提案します。
3. ハイ コントラスト モードと同じように、新しい編集を確認して **Keep** または **Undo** を選択します。
4. エージェントの方針が希望と異なる場合（たとえば、気に入らない方法でトグル ユーザー インターフェース (UI) をリファクタリングする場合）は、チャット入力欄の横にある **Stop** ボタンを選択して停止し、明確な追加プロンプトを送ります。

> [!TIP]
> 実行中のセッションに指示を追加すると、最初からやり直すよりも早く作業を調整できます。追加プロンプトで変更を依頼します。たとえば、「カスケーディング スタイル シート (CSS) を簡潔にし、セレクターの重複ではなく CSS 変数を使う」、「3 つ目のトグルを追加せず、既存の設定パネルにライト モードを組み込む」、「両方のトグルにキーボード ショートカットも追加する」といった依頼ができます。

## 変更されたファイルをレビューする

コミットする前に、エージェントが変更したファイルを一通り確認します。

1. VS Code で **Source Control** ビューを開きます。
2. 変更されたファイルの一覧を確認します。Astro コンポーネント、スタイル、関連テストなどが更新されています。
3. 変更されたファイルをいくつか開き、差分を確認します。カスタム エージェントのアクセシビリティ パターン（Accessible Rich Internet Applications (ARIA) 属性、キーボード操作、セマンティック HTML、local storage による設定の保持）が反映されていることを確認します。
4. 問題がなければ、Source Control パネルから変更を stage してコミットします。次のレッスンで公開します。

## まとめと次のステップ

Copilot Chat agent mode を使い、進行中のセッションを監視して指示を追加しました。ファイル編集を確認し、変更を受け入れたり取り消したりし、コンテキストを失わずに追加プロンプトを送って作業を拡張しました。

この演習では、次のことを確認しました。

- エージェントの作業をリアルタイムで監視しました。
- 個々のファイル編集を受け入れたり取り消したりしました。
- 実行中のセッションに追加プロンプトを送り、作業を調整しました。
